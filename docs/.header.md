## Cloud-init

Every node and the bastion boot from a temporary seed ISO: the module attaches it through the Proxmox API, starts the
VM, waits for cloud-init to finish, then deletes the ISO. It needs no SSH to the Proxmox nodes and leaves nothing on
them, so VMs can migrate freely. The ISO goes on the `local` datastore, which must have the `iso` content type, as
`<cluster>-<role>-<pool>-<index>-cloud-init.iso` (the bastion's is `<cluster>-bastion-cloud-init.iso`), so node
pool names may only use letters, digits, `.`, `_` and `-`.

**API token privileges.** On top of the privileges needed to create and manage VMs, the token needs:
- `Datastore.AllocateTemplate`, `Datastore.Allocate` and `Datastore.Audit` on `/storage/local`, to upload, delete and
  list the seed ISO;
- `VM.Config.CDROM`, `VM.PowerMgmt` and `VM.GuestAgent.FileRead` on the VMs, to attach the ISO, start the VM and read
  cloud-init's result through the guest agent.

Administrator and PVEAdmin roles already include them.

**If a bootstrap fails.** The apply fails when cloud-init reports an error or doesn't finish within 30 minutes, for
example because a package mirror is down. The ISO stays attached for debugging, and the VM keeps running.
cloud-init only runs on a VM's first boot, so applying again doesn't retry it. Replace the VM instead:
```sh
tofu apply -replace='module.<name>.module.node_pool["<pool>"].proxmox_virtual_environment_vm.cluster_node["<n>"]'
tofu apply -replace='module.<name>.proxmox_virtual_environment_vm.bastion[0]'   # the bastion
```
`tofu state list | grep cluster_node` shows the node addresses.

## Upgrading from 0.5.x to 0.6.0

0.6.0 removes the `"snippet"` mode, so first finish the
[0.5.x upgrade guide](https://github.com/GlueOps/opentofu-module-GlueKube-Proxmox/blob/v0.5.0/README.md#upgrading-from-04x-to-050):
every pool and the bastion on `cloud_init = "iso"`, `private_key` removed. Coming from 0.4.x, go through 0.5.x.

Then point `source` at `v0.6.0`, delete every `cloud_init` line from `node_pools` and `bastion` and `private_key` from
`provider_credentials` (the plan names any that are left), and run `tofu init -upgrade`. The plan should show no
changes.
